# 内容审阅工作流与剩余清单

## 当前边界

截至 2026-08-31，目录保留 148 个实验 ID，其中 31 个实验已完成逐项数学与教学审阅，117 个仍为 `unreviewed`。自动生成的学段、目标和前置知识只是迁移草案；来源为空或文案看似完整，都不能替代人工核验。

`index.html` 是未迁移旧实验的运行实现，`experiments_meta.json` 是从旧实现提取的元数据快照，`app/src/data/reviewed-overrides.ts` 只保存已经验收的教育元数据。三者承担不同职责，不允许仅修改目录卡片来掩盖旧实验正文或算法问题。

## 单项验收条件

一个实验只有同时满足以下条件，才能从 `unreviewed` 改为 `verified`：

1. 核对标题、问题状态和适用范围；明确区分定义、定理、猜想、有限计算证据与现实类比。
2. 逐段检查介绍、五个阶段、历史、操作提示和讲解稿；公式、示例、计数与图形至少独立复算一次。
3. 检查互动实现的输入边界、数值精度和算法正确性；近似算法必须说明限制，不能把不完整试除称为素性证明。
4. 给出具体学段、可观察的学习目标和真实前置知识；不使用自动模板目标作为验收内容。
5. 至少提供两个可访问的权威来源。研究结论、发现优先权和当前纪录优先使用原始论文或项目官方页面；教材性概念可以使用大学教材、标准机构或学术数据库。
6. 对会变化的数字注明“截至日期”，审阅时重新访问来源；不得凭旧稿继承“目前”“最新”“已知数量”等表述。
7. 同步旧壳、元数据、讲解文本和目录覆盖；旧壳修改后运行 `npm run catalog:extract`，再执行 `npm run audit:content`。
8. 添加能捕获本次数学纠错或互动边界的自动测试，并通过 `npm test`。涉及画布或交互时还要在实际浏览器完成一次人工路径复核。

审阅记录必须写明：实验 ID、修正的问题、采用的来源、验证结果、审阅日期和仍保留的限制。若任一条件未满足，状态继续保持 `unreviewed` 或临时使用 `in_review`，不能提前计入完成数。
